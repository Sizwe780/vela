# Mathematics domain extension: seven-layer STEM depth
Version: 1.1.0

Each mathematical session contains seven substantive layers:
1. Intuition first: an original hook leading to the precise concept.
2. Visual exploration: an inline interactive graph hook or an explicit, mathematically faithful visual reasoning description. Describe the plotted function and parameter; never reuse a fixed-function widget for an unrelated equation.
3. Procedure: justified algebra, hypotheses and a worked original example.
4. Interpretation: explain the answer, dimensions, domain and limits of the method.
5. Common mistakes: diagnose a plausible misconception and repair it.
6. Assessment: recognition, procedure, error-correction and transfer practice with answer keys.
7. Application: a changed context or meaningful model with stated assumptions.

Use at least six coherent sessions for a module profile marked as a mathematics masterclass. Keep formulas in explicit LaTeX delimiters; strict KaTeX parsing is necessary but not sufficient. Verify signs, domains, theorem conditions, endpoint behavior and exact worked-example results independently. A graph is supporting evidence, not a universal proof. Differentiate conjecture, numerical illustration and proof. Original parameters must be checked against the source exercise inventory when available.

Teaching extensions may add PCK without changing the mathematical claims. These layers are selected by an explicit domain profile, never by assuming every STEM or programming course is mathematics.

## Teaching before calculation
A masterclass states its learning goal, prerequisites and why the method works under explicit hypotheses. Explain symbolic operations and theorem restrictions as visible teaching before original numerical exercises. Place the worked solution and final numerical result behind Show answer. Keep the graph's plotted rule and valid domain explicit; a live graph readout is a visual exploration aid rather than a mark or proof of mastery.
