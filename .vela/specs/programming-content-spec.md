# Programming domain extension
Version: 1.1.0

Build intuition around observable behavior and a precise input/output contract. Explain algorithm or program execution through a worked trace, then test normal, boundary and invalid inputs. Include a debugging/error-correction task and transfer to a changed requirement. State language/runtime assumptions and explain complexity when relevant. Code examples must be original, deterministic and clearly separated from commands the learner should run.

Generated examples are untrusted code, never executed by the content pipeline. Do not import mathematics-only graph conventions or require seven mathematics headings for a programming profile. Universal cognition, originality, feedback, privacy and quality gates still apply. Add future domain-specific hooks through a registered extension, not module-code prefix inference.

## Independent execution and debugging
State prerequisites, the learning goal and why the algorithm works under its input contract before an attempt. Keep exercise output, corrected code and debugging feedback in the answer block. Code fences may contain delimiter-looking strings literally; the exercise parser must not execute code or reinterpret those strings as structural markers.
